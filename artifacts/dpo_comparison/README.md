# Offline DPO exploratory result — 2026-09-27

The completed DPO run did **not** improve this task. Preserve this negative
result; no evaluation-driven tuning or checkpoint selection was performed.

| Condition | Correct action / 60 | Strict JSON valid / 60 | Wrong grant / 50 non-grant cases |
|---|---:|---:|---:|
| Base, minimal prompt | 0 (0%) | 0 | 0 (0%) |
| Base, improved prompt | 0 (0%) | 0 | 0 (0%) |
| SFT | 17 (28.3%) | 60 | 11 (22%) |
| SFT + GRPO | 18 (30.0%) | 58 | 11 (22%) |
| SFT + DPO | 16 (26.7%) | 60 | 21 (42%) |

Wrong grant measures the model's original `grant_reward` choice when the expected
action was different, **before server enforcement**. It is not a count of rewards
actually paid. The base models' zero wrong-grant count is not evidence of safe
use: all their responses violated the strict output format and all scored wrong.

## What was run

- Existing Qwen2.5-0.5B-Instruct SFT from the 2026-09-27 reproduction; no SFT retraining.
- 102 rule-labelled chosen/rejected pairs from the reproduction's GRPO trajectories.
One first-good/first-bad pair per mixed group. All rewards independently rechecked;
only approved training cases contributed.
- Standard sigmoid DPO, beta 0.1, seed 42, one epoch / 51 optimizer steps, batch 2,
learning rate 1e-5. Trainable/default and frozen/ref LoRA adapters share a frozen base.
- Training took 354.78 seconds (~5m55s). 96 LoRA tensors changed; parameter delta
norm 0.0593555. Reference adapter identity stayed equal to the original SFT.
The saved DPO adapter was reloaded and its tensor identity verified.
- 60 new greedy DPO outputs, max_new_tokens=128. The preserved 240 outputs from the
same SFT/GRPO reproduction were reused after provenance checks. Independent
raw-output recomputation exactly matched the saved comparison report.

The initial two-full-model implementation saturated GPU memory and was interrupted
after eight optimizer steps, before evaluation. Its logs are retained locally.
The completed run restarted from original SFT with shared-base adapters; it did
not continue those eight steps. Data and optimization hyperparameters stayed fixed.
After successful training, evaluation model loading stalled and the process ended
before generating any evaluation responses. Evaluation alone was then run in a fresh
process using the verified saved adapter; training was not repeated.

## Interpretation and limits

DPO was one action-correct answer below SFT and two below GRPO. Its JSON formatting
remained valid, while wrong grant choices increased. This supports reporting a
negative result for this particular configuration, not that DPO is generally worse.

This is a one-seed exploratory extension using an already-inspected evaluation
set. Pairs were generated by evolving GRPO policies, so this is not an isolated
algorithm-only comparison. Pair acquisition includes the earlier GRPO compute;
the ~6-minute DPO optimization time is not the full experiment cost. No human
preference data or dialogue-quality reward was used. A chosen action-correct
response may still contain poor dialogue. Human dialogue review is still pending.

## Recompute without a GPU

```bash
uv run python -m quest_npc_lab.slices.dpo_training \
  --source artifacts/dpo_comparison/source \
  --output artifacts/dpo_comparison --recompute
```

`source/final_240_responses.jsonl` is the new reproduction's four-condition run,
not the earlier historical run in the root `artifacts/` directory. `pairs.jsonl`,
`steps.jsonl`, `training_report.json`, `checkpoint_metadata.json`, and raw DPO
outputs preserve the evidence needed to audit selection and results.

Actual adapter weights and the full source reproduction are preserved outside
Git with verified archive backups. They are not included in this PR. Running a
new training requires those source adapters and their complete source reports;
recomputation of the published metrics requires only the checked-in files above.
